# AGENTS.md

Base library for [DINA](https://www.dina-project.net) APIs, built on Spring Boot (Java 25 per `pom.xml`, Maven multi-module, Lombok).

## Modules

- `dina-base-api`: core (entities, services, repositories, validation, controlled vocabularies, auditing, security)
- `dina-filter`, `dina-json`, `dina-client`: filtering, JSON/JSON:API helpers, client
- `dina-messaging`, `dina-search`, `dina-workbook`: RabbitMQ messaging, search indexing, workbook handling
- `dina-test-support`: published test utilities (e.g. `PostgresTestContainerInitializer`)
- `docs/`: AsciiDoc documentation, generated by `mvn clean compile` into `target/generated-docs`

## Build and test

- Compile everything: `mvn -o test-compile` (use `-pl <module> -am` for one module plus its siblings; sibling SNAPSHOT artifacts are not otherwise resolvable)
- Unit tests run with surefire (`*Test`); integration tests (`*IT`) run with failsafe and need Docker (Postgres Testcontainers).
- Static analysis: Checkstyle and SpotBugs are configured in the root `pom.xml` (`spotbugs-exclude.xml`, `owasp-suppression.xml`). Keep code compliant.

## Conventions

- Entities implement `DinaEntity` (requires `getCreatedBy()` / `getCreatedOn()`).
- Integration tests use `@SpringBootTest(classes = TestDinaBaseApp.class)` with `@ContextConfiguration(initializers = PostgresTestContainerInitializer.class)`.
- Test-only helper classes that are used by a single test belong as nested classes in that test, not as separate files.
- Use Lombok (`@Data`, `@Builder`) for simple models; see `lombok.config`.
- Update `docs/*.adoc` when changing documented behavior.
